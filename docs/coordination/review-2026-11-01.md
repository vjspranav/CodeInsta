## Bugs and security issues by severity

### High — fix before unattended publishing or replies

1. **B1: A private answer can go to the wrong member.** `src/app/api/agent/messages/route.ts:46` chooses the most recently active user across likes, feedback and messages when no feedback ID is supplied. It does not bind the recipient to the message being answered or even scope that fallback activity to this creator. A member liking any reel after an owner's DM can become the recipient of the owner's answer. The existing feedback-ID branch correctly scopes feedback to creator. **Fix:** require either `feedback_id` or `reply_to_message_id`; fetch the original event under the authenticated creator and derive its immutable `user_id`. Return the reply target ID in inbox, reject missing/foreign targets, and atomically insert reply/mark answered with an idempotency key. Add a two-user, two-creator race regression. Codex removed the unsafe no-feedback command from its playbook; Claude must fix the route, CLI and Claude playbook.

2. **B2: `owner-sync` bypasses the Google-identity owner rule.** `scripts/invite.ts:39` filters by allowlisted email alone and upserts `role='owner'`. `supabase/migrations/0003_members_invites.sql:29` grants owner powers based on that row, so frontend `isOwnerUser` checks do not protect direct database RPCs after this elevation. This is a conditional administrative-tool privilege escalation path, not evidence it has been exploited. **Fix:** reuse the same verified Google-identity plus allowlisted-email predicate as `src/lib/supabase/allowlist.ts`, paginate `listUsers` rather than stopping at 1000, and add allowlisted password-only/unconfirmed/Google identity tests. Separately audit existing owner rows in a controlled authorized maintenance task; this review made no production calls or role changes.

3. **B3: Final-story QA has no publishing enforcement boundary.** `src/app/api/agent/reels/route.ts:34` validates the legacy contract; `scripts/agent.ts` posts the reel before generating/uploading Kokoro audio. Neither path accepts a validated v3 story with its complete render receipt. Render's `--no-verify` is only a local convention. **Fix:** implement the Q4 pipeline with immutable media hashes, a trusted complete gate result and atomic publication. Do not accept a caller's unverified `passed:true`. Preserve debug renders as nonpublishable artifacts. Codex updated its playbook to prepare final drafts locally and defer publication until this exists. This is a release-quality/control failure, not an unauthenticated API bypass.

### Medium — correctness, safety boundaries and owner feedback

4. **B4: Audio QA gives misleading comfort.** `render/verify-lib.ts:171`/`:773` excludes lead-in and end card, treats every millisecond of every clip as speech and checks no role WPM. Latest parts pass the current pure timing gate at 9.65%/9.82% inter-line silence but already have 17.09%/21.20% whole-video silence before internal clip pauses. Original senior is about 108 WPM. A 60 s invented audio-manifest entry passes the pure gate without a file or any speech. **Fix:** A2/A10/Q5/Q6, measured from the encoded artifact, with fixtures for silent/stale/misbound audio. Keep approximate rates in this report distinct from transcription-aligned rates.

5. **B5: Readability and reveal coverage misses actual defects.** `DBTable.tsx:137`/`:213` renders 12 px headers/14.5 px data with clipping/ellipsis; `verify-lib.ts:370` checks only labels, not data. Sample question at `instagram-feed-part1.json:428` includes the answer before the response. `captionstate.ts:91` invents word positions, and `Story.tsx:26` holds an old beat through `end+6` frames. `state.ts:114` aggregates future commit updates. `Overlays.tsx:98` drops glossary entries beyond eight. **Fix:** V3–V7/V12–V16; add deliberate failing fixtures for tiny data, early answers, long glossaries and a future commit update. Check transition frames and end cards, not just scene-end geometry.

6. **B6: Member isolation exists as instructions, not a verified runtime boundary.** `agents/*/PLAYBOOK.md` asks for an isolated writer, but there is no invoked, capability-restricted implementation in the creator CLI. Raw approved topics and open member feedback enter the orchestrator inbox. Approval does not neutralize embedded instructions. **Fix:** tool-less writer plus quoted/minimal input, typed output validation, and adversarial tests proving no tools/secrets/private threads are available. Use a structured writer result and the immutable B1 reply target. The Codex playbook now fails closed when `from_owner` is absent or isolation unavailable. Do not count prose alone as proof of isolation.

7. **B7: Feedback selection cannot implement net-disliked pairs or the owner’s ML ladder.** `inbox/route.ts:28` stores marginal counts only; recent likes at `:170` omit owner identity, dislikes omit `from_owner`, and catalog omits genre/style/ML level. `content/curriculum.md` asks for L1–L5 in `level`, while schema and SQL allow only beginner/intermediate/advanced. **Fix:** pair counts, owner-derived feedback markers, creator-scoped chronological level history, and a coordinated `ml_level` contract/migration. Add deterministic selection tests for two-of-last-three advancement and new-angle retry. Codex fixed legacy genre/style rejection; the incompatible ML storage contract requires Claude coordination before the owned schema can safely change.

8. **B8: Inbox can lose events before processing.** `src/app/api/agent/inbox/route.ts:157` writes the new last-run timestamp after reading likes/dislikes; events inserted between the read and this marker fall behind the next `since`. The route also marks unread DMs read before the caller has successfully answered. **Fix:** capture a high-water timestamp before querying and return it as a cursor, query a bounded interval, and acknowledge processed event IDs only after successful work. Retry must be idempotent. Test an event arriving between selection and acknowledgment and a failed response/send.

9. **B9: Request fulfillment and answer marking are not atomic.** `src/app/api/agent/reels/route.ts:76` inserts a reel, then updates feedback/request state at `:98`/`:106`. A nonexistent, rejected or already-done request can update zero rows without error yet return 201; partial failures leave a posted reel with an open request, inviting duplicate retries. `messages/route.ts` has the same insert-then-answer-mark pattern. **Fix:** transactional RPC with row locks, creator/request checks, expected row-count assertions and an idempotency key. Reject invalid fulfillment before committing the reel, and roll back all state on failure.

10. **B10: Pending-topic quota races.** `supabase/migrations/0004_interests.sql:61` counts pending requests without a per-user lock. Concurrent inserts can each observe fewer than five and exceed the cap. The feedback quota in `0005_member_asks.sql:28` already demonstrates an advisory transaction lock. **Fix:** add the equivalent per-user lock around pending-request count/insert and a concurrent-insert regression. This needs a new migration, not an edit to applied history.

11. **B11: New-category assignment is incomplete and unstable.** `inbox/route.ts:99` includes only categories with `created_from_request`, excluding owner-added empty categories. The returned list drops categories after a reel exists; assigning even/odd list indexes anew can reassign the remaining categories to the other creator. **Fix:** persist a category creator/claim or stable allocation index, include owner-created categories, and test assignment before/after another category receives its first reel. Codex playbook now requests curriculum edits from Claude rather than crossing ownership.

12. **B12: Metadata compatibility fallback silently defeats preferences.** `reels/route.ts:78` retries inserts without genre/style if columns are absent; inbox suppresses all errors in preference queries into empty stats. Final v3 output cannot satisfy mandatory metadata or reliable feedback this way. **Fix:** capability checks and explicit actionable errors for final publishing; limit old-schema fallback to explicitly identified legacy reads/maintenance, and surface non-schema query failures. Apply migrations only through an authorized deployment task, not this review.

13. **B13: TTS cache does not capture its full generation recipe.** `scripts/lib/tts-v3.ts:276` hashes caller style (empty when defaulted), speed and a static `v3` marker, but not resolved default voice prompts, pause-compressor configuration or reference-clip content. Changing those can reuse stale slow audio. **Fix:** hash resolved prompt, selected voice/model, reference digest, lexicon-normalized text and a postprocessor version/config. Test cache invalidation independently of paid providers.
